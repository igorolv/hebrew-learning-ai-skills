# Домашнее задание по ивриту: Markdown → DOCX

Преобразовать один или несколько Markdown-файлов из `hebrew-homework-solve` в DOCX,
сохранив ивритский RTL/BiDi, смешанные русско-ивритские фрагменты и таблицы упражнений.

## Вход и выход

Принимать файлы:

```text
ДЗ_урок_{N}_часть_{M}.md
ДЗ_урок_{N}_часть_{M}_слайды_{СЛАЙДЫ}.md
```

Создавать один DOCX на каждый входной файл, заменяя `.md` на `.docx`.
При нескольких входах не объединять документы.

## Маршрутизация и границы

- Использовать `scripts/build_homework_docx.py` как единственный builder DOCX.
- Не переписывать генератор на JavaScript и не использовать `docx-js`.
- Не применять общие дизайн-пресеты: визуальный контракт этого скилла уже задан.
- Использовать общий document skill только для выбора bundled runtime.
- Не изменять исходный Markdown. Все выходы и временные файлы создавать в рабочей директории
  пользователя, а не в каталоге скилла.
- Не запускать `hebrew-homework-solve` автоматически при отсутствии входа, кроме режима
  `hebrew-homework-pipeline`. В самостоятельном режиме сообщить, какой Markdown нужен.

## Рабочий процесс

### 1. Проверить вход

Убедиться, что каждый Markdown:

- начинается с `# Домашнее задание`;
- содержит хотя бы один заголовок `## Слайд` или `## Слайды`;
- содержит корректные Markdown-таблицы, если в нём есть упражнения со списками.

При ошибке показать конкретный файл и строку. Не создавать частичный DOCX.

### 2. Выбрать Python runtime

Использовать Python, предоставленный текущей workspace-средой. Не использовать системный Python,
если доступен bundled runtime. Проверить зависимость:

```bash
python -c "import docx"
```

Устанавливать `python-docx` только если импорт не работает и текущая среда разрешает установку.

### 3. Запустить bundled builder

Передавать абсолютные пути:

```bash
python "/absolute/path/to/hebrew-homework-docx/scripts/build_homework_docx.py" \
  "/absolute/path/to/ДЗ_урок_N_часть_M_слайды_X-Y.md" \
  -o "/absolute/path/to/ДЗ_урок_N_часть_M_слайды_X-Y.docx"
```

Флаг `-o` использовать только с одним входным файлом. Для нескольких файлов запускать builder
без `-o` из рабочей директории с нужными выходными путями либо обрабатывать файлы по одному.

### 4. Проверить структурный контракт

- Иврит: David 18 pt, RTL, выравнивание вправо, complex-script свойства.
- Русский: Arial 10 pt, LTR, выравнивание влево.
- Смешанный текст: отдельные runs с настройками соответствующего языка.
- Таблицы упражнений: широкая колонка «Текст», узкая колонка «№», фиксированная геометрия.
- Строки таблиц не разрываются между страницами.
- Каждое новое упражнение начинается с новой страницы.
- Жирное/курсивное inline-форматирование из Markdown сохраняется.

Bundled script является источником истины для OOXML-деталей. Не копировать в рабочий код
псевдопримеры из документации.

### 5. Выдать результат

Вернуть пользователю только итоговые DOCX, если он не запросил Markdown.
Использовать абсолютные ссылки на файлы средствами текущей среды.
