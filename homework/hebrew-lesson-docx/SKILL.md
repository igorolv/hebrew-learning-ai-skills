# Шпаргалка по ивриту: Markdown → DOCX

Преобразовать Markdown из `hebrew-lesson-enrich` в иерархический DOCX со справочными таблицами,
контрастными примерами, blockquote-правилами и корректным RTL/BiDi.

## Вход и выход

Принимать:

```text
Шпаргалка_по_{N}_уроку_{M}_часть.md
```

Создавать файл с тем же именем и расширением `.docx`. При нескольких входах создавать отдельный
DOCX для каждого файла.

## Маршрутизация и границы

- Использовать `scripts/build_lesson_docx.py` как единственный builder DOCX.
- Не переписывать генератор на JavaScript и не использовать `docx-js`.
- Не применять общие дизайн-пресеты: визуальный контракт учебной шпаргалки уже задан.
- Использовать общий document skill только для выбора bundled runtime.
- Не изменять исходный Markdown. Создавать выходы и временные файлы в рабочей директории
  пользователя, а не в каталоге скилла.
- Не запускать `hebrew-lesson-enrich` автоматически при отсутствии входа, кроме режима
  `hebrew-homework-pipeline`. В самостоятельном режиме сообщить, какой Markdown нужен.

## Рабочий процесс

### 1. Проверить вход

Убедиться, что Markdown:

- начинается с `# Шпаргалка` или `# Грамматика`;
- содержит хотя бы один нумерованный раздел `# N.`;
- содержит корректные Markdown-таблицы.

При ошибке показать конкретный файл и строку. Не создавать частичный DOCX.

### 2. Выбрать Python runtime

Использовать Python, предоставленный workspace-средой. Не использовать системный Python,
если доступен bundled runtime. Проверить зависимость:

```bash
python -c "import docx"
```

Устанавливать `python-docx` только если импорт не работает и текущая среда разрешает установку.

### 3. Запустить bundled builder

Использовать абсолютные пути:

```bash
python "/absolute/path/to/hebrew-lesson-docx/scripts/build_lesson_docx.py" \
  "/absolute/path/to/Шпаргалка_по_N_уроку_M_часть.md" \
  -o "/absolute/path/to/Шпаргалка_по_N_уроку_M_часть.docx"
```

Флаг `-o` использовать только с одним входным файлом. Несколько файлов обрабатывать по одному
или запускать builder без `-o` в подходящей рабочей директории.

### 4. Проверить структурный контракт

- Заголовок документа: Arial 16 pt, центр.
- Нумерованные разделы: Arial 14 pt; разрыв страницы перед каждым разделом, кроме первого.
- Подразделы: 13 pt; подподразделы: 12 pt.
- Иврит: David 18 pt, RTL, complex-script свойства.
- Русский: Arial 12 pt, LTR.
- Таблицы: фиксированная геометрия, повторяемое форматирование заголовков, строки не разрываются.
- Blockquotes: синяя левая граница и отступ.
- Символ `↳` в таблицах: Arial; следующий ивритский фрагмент: David RTL.
- Маркированные списки и inline bold/italic сохраняются.

Bundled script является источником истины для OOXML-деталей.

### 5. Выдать результат

Вернуть пользователю только итоговые DOCX, если он не запросил Markdown.
Использовать абсолютные ссылки на файлы средствами текущей среды.

## Справочные файлы

Эталонные входные Markdown находятся в `references/`.
